# Economic Reasoning Principles

Fifteen reusable rules behind the Value-to-Action framework.

## 1. The model is not the system
`Model Cost → Full Execution Cost → Total Relevant Customer Cost`

## 2. A response is not Accepted Work
Count useful work only after task success and mandatory quality/control floors are satisfied. Failed work still consumes resources.

## 3. Unknown is not zero, false, or not applicable
`Unknown ≠ Zero ≠ False ≠ Not Applicable`

## 4. Every arrow in the value chain is an evidence claim
`AI Work → Accepted Work → Business Outcome → Economic Value`

## 5. Observed outcome is not incremental outcome
`Order after AI ≠ Order caused by AI`

## 6. Define treatment before observing success
Treatment assignment precedes Accepted Work and the outcome. Failed treatment work stays in the treatment denominator.

## 7. Value and cost must share one economic basis
Match population, time period, and workload scope before calculating Net Economic Value.

## 8. Historical economics do not answer the next-dollar question
`ΔNEV = ΔValue - ΔCost`. Define the proposed increment first.

## 9. Cost behavior matters
Variable, fixed, shared, sunk, and step-function costs behave differently. Average cost can differ materially from marginal cost.

## 10. Evidence Confidence and Value Resilience are different
Evidence Confidence asks how strongly a claim is supported. Value Resilience asks how easily the economic conclusion breaks.

## 11. Sensitivity is not evidence
Changing assumptions shows how the model responds; it does not establish which assumption is true.

## 12. High uncertainty × high sensitivity is an evidence priority
Spend measurement effort where a variable is both poorly known and capable of changing the decision.

## 13. Decision gates are not scores
`High Value + Failed Mandatory Control ≠ Approval`

## 14. Select the action from the deficit, not the headline metric
`Evidence deficit → PROVE`, `Execution deficit → OPTIMIZE`, `Structural deficit → RESTRUCTURE`.

## 15. Every action must buy progress and define reassessment
PROVE should buy information. OPTIMIZE should improve execution. RESTRUCTURE should fix the surrounding system. SCALE should deploy justified capital. Every action should define what happens next and what evidence/event causes reassessment.
